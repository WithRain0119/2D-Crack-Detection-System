# 水工建筑物智能巡检分析系统

## 背景

本项目为华北水利水电大学校级大创项目，核心功能为对水工建筑物表面的裂缝进行识别。未来会逐步地扩展识别缺陷的种类。

本系统面向水工建筑物日常巡检中"人工查看裂缝照片效率低、缺少记录留存"的实际需求，提供从**图片上传 → 批量识别 → 结果回看 → 历史追溯**的完整闭环。当前版本为重构完成版：前后端分离、代码模块化组织、检测历史持久化，部署在本地即可开箱使用，也可作为后续缺陷种类扩展的基础平台。

## 项目技术栈


| 层级         | 技术选型                          | 说明                                                                                 |
| ------------ | --------------------------------- | ------------------------------------------------------------------------------------ |
| 深度学习框架 | PyTorch（CPU 版）+ Ultralytics    | YOLO 目标检测框架，加载本项目训练好的权重`models/version2.pt`（crack 单类别）        |
| 后端框架     | Python 3.12 + FastAPI + Uvicorn   | 轻量异步 Web 框架，提供批次管理、识别推理、历史查询等 REST 接口                      |
| 数据存储     | SQLite（Python 标准库`sqlite3`）  | 检测历史持久化，重启后可查，零额外部署成本                                           |
| 图像处理     | Pillow（PIL）                     | 图片合法性预检、识别结果图绘制保存                                                   |
| 前端         | 原生 HTML5 + CSS3 + JavaScript    | 零框架、零 CDN、无任何外部网络依赖，浏览器直接打开即可使用；按模块拆分为多个文件组织 |
| 运行环境     | Windows + Conda（`yolo_v1` 环境） | 单机本地部署，前后端通过本地 HTTP 接口通信                                           |

## 一、系统概述

重构完成后的系统具备以下核心能力：

**识别流程**

- **三种选图方式**：选择整个文件夹、选择单/多张图片、将文件或文件夹直接拖入页面（拖入文件夹自动递归读取其中图片并**立即开始分析**，无需二次操作）；
- **批次流水线**：图片按上传时间归档到 `static/<批次时间>/input|output/`，同名自动加后缀不覆盖，非图片自动过滤，单批次上限 500 张；
- **置信度调节**：滑块调整识别阈值（0.05~0.9，默认 0.25），随本次分析生效；
- **实时进度**：进度条、已处理张数、当前识别文件名，全部读取后端真实进度。

**结果查看**

- **原图 / 识别结果左右对比**，顶部标注当前对比的原图文件名，点击左侧缩略图切换（缩略图带待处理/处理中/完成/失败四态标注）；
- **裂缝明细表**：每条裂缝的像素坐标、归一化坐标（0~1）、置信度，表格列与表头严格对应；
- **历史记录栏**：显示上传文件名、存储位置、识别时间、裂缝数量与结果缩略图，支持点击查看回放大图；基于 SQLite 持久化，**后端重启后依然可查**。

**设置与交互**

- **分类设置界面**（右上角 ⚙）：左侧分类导航 + 右侧内容的居中模态窗，「通用」页提供清空日志文件、清空历史检测记录两项，外观 / 模型 / 关于为预留占位栏（后续扩展）；
- **自绘交互组件**：删除操作使用统一的确认对话框（确认/取消），操作结果显示在右下角提示条（成功显示清除条数、失败显示原因，2 秒后自动消失）；
- **三级状态提示**：顶部状态条（后端离线红 / 模型未加载黄 / 在线绿）、缩略图状态徽章、结果区提示，异常不白屏；
- **运行日志分级**：终端仅输出核心流程与警告报错，每请求、每张图的识别明细完整写入 `log/` 日志文件。

**可靠性**

- 单实例进程锁（防止重复启动、残留锁自动清理）；分析中断开后端会明确提示连接失败；轮询支持取消（切换批次即作废旧进度）。

## 二、重构步骤

本次重构按"**后端 → 前端 → 文档 → 验收**"四个步骤分步实施，每一步独立测试通过后再进入下一步，保证每一步都可验证、可回退。**四个步骤现已全部完成**，整体验收（25 项接口断言 + 浏览器交互测试）全部通过。

### 步骤一：后端重构 ✅

**采用技术**：Python 3.12 + FastAPI + Ultralytics YOLO + SQLite + 多线程推理。

**如何重构**：将最初版本混乱的后端代码拆分为 8 个单一职责模块，统一按接口契约实现，核心改动包括：

1. **模块化拆分**——每个文件只负责一件事，模块间单向依赖，消除原版本职责纠缠、难以维护的问题；
2. **批次流水线**——"创建批次 → 图片落盘 → 后台逐张识别 → 结果图输出"四段式流程，图片按上传时间归档到 `static/<批次时间>/input|output/`；
3. **SQLite 持久化**——检测记录（上传了哪些图、存在哪里、识别效果）写入 `backend/history.db`，重启后历史不丢失；
4. **单实例保护与运行日志**——进程锁防止重复启动；每次启动自动生成带时间戳的日志文件，全链路记录启动、请求、推理、异常信息，便于排查问题；
5. **推理与服务解耦**——YOLO 推理固定在独立线程池中串行执行，接口响应不被慢速推理阻塞。

**实现的功能**：后端健康检查、批次创建与上传（含同名去重、非图片过滤、500 张上限）、启动识别、进度轮询、历史批次列表、检测记录查询与清空、单张兼容检测、清空日志。

**文件功能说明**：


| 文件                 | 功能                                                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `backend/main.py`    | 程序入口：按顺序执行"目录自检 → 抢占实例锁 → 初始化日志 → 加载模型 → 恢复历史批次 → 启动服务"                     |
| `backend/config.py`  | 全局常量集中定义：地址端口、模型路径`models/version2.pt`、时间格式（日志与批次命名统一）、图片扩展名白名单、数量上限等 |
| `backend/logger.py`  | 日志系统：每次启动在`log/` 下新建一个时间戳日志文件；日志文件记录全量明细，控制台按级别分流，仅输出核心流程与警告报错  |
| `backend/lock.py`    | 工作目录自检（必须从项目根目录启动）+ 单实例锁（原子创建锁文件、进程存活探测、残留锁自动清理）                         |
| `backend/yolo.py`    | 模型加载与单图推理：图片合法性预检 → CPU 推理 → 输出裂缝框、裂缝数量、图像尺寸、耗时 → 绘制并保存结果图             |

| `backend/batches.py` | 批次核心逻辑：批次创建与图片存储、同名去重、后台识别任务调度、进度状态维护、启动时扫描磁盘恢复批次                     |
| `backend/routes.py`  | HTTP 接口层：注册全部路由、跨域配置、每个请求的方法/路径/状态码/耗时日志中间件、静态图片服务                           |

## 四、使用说明

1. **启动后端**（见「六、启动方式」），确认控制台出现监听信息；
2. **打开前端**：双击 `水工建筑物智能巡检分析系统.html`，顶部徽章变绿即代表后端就绪；
3. **选择图片**：点「📁 选择文件夹」整夹上传、「🖼️ 选择图片」选单/多张，或**直接把文件/文件夹拖进虚线框**（拖拽会自动开始分析，点按钮方式选完后需手动点「开始分析」）；
4. **调整置信度阈值**（可选）：拖动滑块，值越低检出越多、误检风险越高；
5. **查看进度**：分析过程中进度条与缩略图实时更新；
6. **查看结果**：点击左侧缩略图，右侧切换原图/识别结果对比，下方明细表列出每条裂缝的像素坐标、归一化坐标与置信度；
7. **回看历史**：页面底部「历史检测记录」展示历次识别（后端重启后仍在），点「查看」回到大图对比；
8. **设置**（右上角 ⚙）：「通用」页可清空历史日志文件与历史检测记录（均有确认对话框与右下角结果提示）；点右上角 ✕ 关闭。

## 六、启动方式

**环境要求**：Windows + Conda 环境 `yolo_v1`（已包含全部依赖）。

```powershell
# 1. 进入项目根目录（必须在根目录启动，否则找不到模型与静态目录）
cd ~\2D-Crack-Detection-System

# 2. 解压权重文件到models文件夹中

# 4. 启动后端

# 5. 启动前端：双击打开 水工建筑物智能巡检分析系统.html（或拖入浏览器）
```

- 后端地址：`http://127.0.0.1:8000`，启动成功后控制台会打印监听信息，`log/` 下生成本次运行日志；
- **终端输出为分级精简模式**：控制台只显示核心流程（启动、模型加载、批次创建/启动/完成等）与警告报错；每请求、每张图识别明细等完整日志仅写入 `log/` 日志文件，排查问题时查看对应文件即可；
- 前端打开后自动探测后端状态，绿色即代表就绪，即可选择图片开始分析；
- 关闭后端：直接关闭控制台窗口（或任务管理器结束进程），下次启动会自动清理残留锁文件。

## 七、常见问题

1. **提示"已有实例正在运行"**：后端同一时间只允许启动一个实例，属正常保护；若确认没有实例在跑，删除 `backend/running.lock` 后重启即可（进程被强制结束时可能残留）。
2. **端口被占用（WinError 10048）**：执行 `netstat -ano | findstr :8000` 找到占用进程并结束，再启动后端。
3. **前端红色提示"后端未启动"**：先按上述步骤启动后端，再刷新页面。
4. **必须从根目录启动**：模型 `models/version2.pt`、日志目录、静态目录均按相对路径定位，从其他目录启动会加载失败。
5. **批次文件夹名中的全角冒号**：Windows 文件名不允许半角冒号，故日志与批次目录时间戳使用全角冒号（`：`），属正常现象。
6. **点"选择文件夹"时浏览器弹出"是否上传到此站点"**：这是 Chromium 系浏览器对文件夹选择的强制安全确认，网页无法去除，点"上传"继续即可；改用**直接拖拽文件夹**进页面则不会出现该确认，且拖完会自动开始分析。

## 八、当前局限与改进方向

立足校级创新训练项目的定位，当前版本优先保证核心识别功能完整可用，以下方面留待后续迭代：

1. **推理速度**：当前固定使用 CPU 推理以保证兼容性，大批量图片处理耗时较长；后续可加入 GPU 加速，显著提升批量识别效率。
2. **缺陷种类**：目前仅支持裂缝（crack）单类别识别，与背景中"逐步扩展识别缺陷种类"的规划一致，后续将随训练数据扩充类别。
3. **识别精度**：精度依赖训练数据的规模与多样性，对光照、纹理等复杂现场条件的泛化能力有待更多实测数据持续优化。
4. **交互实时性**：进度采用每秒轮询方式获取，后续可升级为 WebSocket/SSE 推送，图片多时更节省资源。
5. **存储管理**：识别结果会持续占用磁盘，暂未提供自动清理策略；历史记录查询暂未提供分页，数据量极大时可考虑补充。
6. **使用场景**：系统定位为本地单用户工具，未设计多用户并发与权限管理，后续如需多人协同可在此方向扩展。
7. **设置界面**：外观 / 模型 / 关于三个分类目前为占位栏，具体设置项待后续设计补充。
